Logical Depth

Lesson 2 left you with two objects carrying essentially the same information: Ω’s first n bits, and the table of which programs up to n bits halt. One is a random string nobody can use; the other is a lookup table. K(x) can’t tell them apart: both are about n bits. Lesson 3’s sophistication can (Ω’s bits are random, so low; the halting table has near-maximal sophistication), but it counts bits of model, not the work of decoding. Logic lesson 9 drew a similar existence-versus-time line for proofs: “Completeness says a proof exists. It says nothing about how long it takes to find one…” This lesson measures a different quantity, in steps rather than bits: how long x’s best explanation takes to run. By the end you can place any described object on a two-by-two map (compressible or not, shallow or deep) and say why.

Buried redundancy: what an ephemeris is worth

Charles Bennett’s 1988 paper starts from value. A table of planetary positions “has no more information than the equations of motion and initial conditions from which it was calculated, but saves its owner the effort of recalculating these positions.” A coin-toss sequence has more information and no value.

Buried Redundancy / Value of a Message Value lies neither in a message’s information nor in its obvious redundancy, but in its buried redundancy: “parts predictable only with difficulty.” In Bennett’s words, “the value of a message is the amount of mathematical or other work plausibly done by its originator, which its receiver is saved from having to repeat.”

“Plausibly” is the same Occam step as Solomonoff induction: the minimal program is the best explanation, so running it is the output’s “most plausible causal history.” Depth formalizes stored computation, not information.

The definition: the fastest near-shortest program

Logical Depth Ds(x) D_s(x) = min { T(p) : U(p) = x and |p| ≤ K(x) + s }: the running time of the fastest self-delimiting program for x among those within s bits of the shortest. This is the simple variant of Antunes et al. and Wikipedia; Bennett’s final Definition 1 asks instead that the program be s-incompressible, which differs technically, not in spirit.

Why the fastest? Prefix any program with loop 10^100 times and it gets slower, so “how long some program runs” measures nothing. The minimum asks a sharp question: is there any plausible quick route to x? A larger s admits more programs, so D_s(x) is non-increasing in s.

Significance Level s (why not just the minimal program’s runtime?) Bennett’s Tentative Definition 0.1, “the execution time of its minimal program,” is unstable: when a much faster program is only a few bits longer, “slight changes in x may induce arbitrarily large changes in the run time of the minimal program.” The parameter s turns depth into a claim with a confidence level.

Example: a 1,000-bit x has a 1,005-bit minimal program running 2^60 steps, and a 1,010-bit print program running about 1,000. Definition 0.1 says 2^60; a tweak that adds 6 bits to the slow program makes print minimal, and the answer drops to about 1,000. But D_5(x) ≈ 1,000 either way, which is the honest reading: the evidence for a slow origin was only 5 bits.

Under lesson 4’s m(x), s extra bits cost a factor 2^(−s) in weight. So D_s(x) = t says every route to x in fewer than t steps is more than 2^s times less plausible than the best one, or, in Bennett’s Tentative Definition 0.3, “less plausible than for the first s tosses of a fair coin all to come up heads.”

Shallow at both ends of K

  • Random x, with K(x) ≈ |x|. The print program has length |x| + O(log |x|), so it is within O(log |x|) bits of minimal, and it copies x in linear time. Maximal K, minimal depth.
  • Trivial x, such as 0^n for a typical n. An O(log n)-bit program writes it in linear time. Shallow.

Both extremes of lesson 3 come out shallow. So deep implies compressible: a deep string needs a program much shorter than print, with no fast rival within s bits. The incompressible-and-deep cell is empty.

How fine-grained is “deep”? K is machine-independent up to an additive constant. Depth is preserved only up to a linear slowdown plus a constant shift in s between Bennett’s efficiently universal machines, and up to a polynomial across broader models (Bennett, pp. 2, 17). So “deep” separates polynomial from exponential, not 3n from n. That makes π’s digits a gray case: Bennett calls them nontrivial, but Gauss–Legendre gives n digits in O(M(n) log n) steps, with multiplication M(n) = O(n log n) by the best known algorithm (Wikipedia). Quasi-linear, so shallow.

Ω is shallow, the halting table is deep

Busy Beaver Function B(n) Bennett’s definition: the greatest number computable by a self-delimiting program of at most n bits. (Aaronson et al. use the closely related longest running time of a halting k-bit program.) Like Radó’s Turing-machine version, it eventually exceeds every computable function (Wikipedia). For scale: the 5-state Turing-machine record, 47,176,870 steps, was proven maximal only in 2024, and as of 2026 a 6-state machine is known to run past 2↑↑↑5 steps.
Theorem (Bennett): Ω is a shallow representation of the deep object K₀ Ω’s first n bits are algorithmically random, so their depth grows only linearly. The first 2^n bits of the halting set K₀ follow from them by dovetailing, but that decoding takes between B(n − O(1)) and B(n + H(n) + O(1)) steps, which grows faster than any computable function of n. Going the other way is fast: Ω’s first n bits can be read off quickly from the first 2^(n + H(n) + O(1)) bits of K₀.

The dovetailing decoder can’t finish before the slowest halting n-bit program does. Same n bits of information, but Ω holds no buried redundancy (that is why it is random), while the table holds Busy-Beaver-sized buried redundancy. Bennett calls Ω “ambitious but shallow”: it tells you how to compute huge numbers without being evidence that anyone did.

The slow growth law: depth is evidence of history

Slow Growth Law (Bennett’s Theorem 1) For significance levels s₂ > s₁, a program q generated by coin tossing turns x into an output whose s₂-significant depth exceeds D_s₁(x) + T(q, x) + O(1) with probability less than 2^(−(s₂−s₁)+O(1)).

Fast deterministic processes cannot make shallow objects deep; fast random ones do so only by a lucky guess costing about s₂ − s₁ bits. So a deep object is evidence of a long computation in its past. That is Bennett’s motivation: things like “the human body” that “contain internal evidence of a nontrivial causal history.”

Only an upper bound Long computations can still give shallow outputs: loop 10^100 times, then print a million zeros. Depth uses the fastest plausible route, not the route taken. Whether objects much deeper than their own length can be generated efficiently, Bennett ties to unproven assumptions: cryptographically strong pseudorandom functions would allow it, while if P = PSPACE a finite system could reach only polynomially deep states. Both questions are still open as of 2026.

Four notions, four questions

Lesson 3 called sophistication “a third notion again.” Depth is a fourth. Keep them apart by what each one counts:

  • K(x), bits: how short is the shortest description?
  • Sophistication, bits: how large is the model in the best two-part code?
  • Depth, steps: how long does a near-shortest explanation take to run?
  • Crypticity, steps: given x, how long does it take to find a plausible explanation?

Depth and sophistication agree at the extremes (Antunes et al. name “the random strings and the efficiently computable ones” as non-deep) and split in the middle. Run a simple rule from a simple start for t steps. Initial state, rule and t describe the result, so by a two-part code its sophistication “can never exceed log(t)+c” (Aaronson). If that program is near-minimal, its depth is at most about t, the program’s running time, and it can approach t when no shortcut beats simulation.

The one rigorous bridge Rescale depth to bits with the inverse Busy Beaver function, bb(t) = the length of the shortest halting program running at least t steps. Antunes et al. (2017) prove bb(depth) and sophistication agree within O(log |x|), with logarithmic slack in significance; Bennett had called his D_bb “closely related” to Koppel’s sophistication. The cost: for any computable f, bb(f(n)) ≤ K(n) + O(1) = O(log n), so every depth bounded by a computable function of the length (2^n, say) vanishes into the error term.
Cryptic vs. Deep Bennett calls an object cryptic when finding its plausible origin “is like solving a cryptogram.” Encrypt a megabyte of zeros under a random 128-bit key: if the cipher is secure, the ciphertext looks random, yet K is about 128 bits plus O(log n), and that program runs fast. Compressible, shallow, cryptic, or in Bennett’s words “shallow … but cryptic.” An RSA modulus likewise: quick to generate, believed hard to factor.
Depth is uncomputable, by the same move again If a program computed D_s(x) for a fixed s, you could run every program up to print’s length plus s bits for D_s(x) steps and keep the shortest that outputs x. Its length m satisfies K(x) ≤ m ≤ K(x) + s, and lesson 1’s Berry argument rules that out too: search for the first x whose estimate is at least N + s. So “depth meters” such as decompression time (Zenil et al.) are heuristics that “depend on the compression algorithm used.”

Check your understanding

1. Why does Bennett use the fastest program within s bits of minimal, rather than the minimal program’s own running time?

2. A string of n fair coin flips has K(x) ≈ n, the maximum. What is its depth at any reasonable significance level?

3. Ω’s first n bits and the first 2^n bits of the halting table K₀ carry about the same information. Why is the first shallow and the second deep?

4. Which statement does the slow growth law actually support?

Practice before next lesson

Pick one real artifact: a chess endgame tablebase, Bennett’s planetary ephemeris, a fossil, or a sorted list of a million random numbers. On paper, write (1) its shortest plausible explanation and a rough K in bits; (2) the fastest program within a few bits of that, with a rough step count as a function of the object’s size; (3) its cell on the map, at a stated s; (4) which part is buried redundancy, the work its receiver is spared. Then ask: is its depth large relative to its own length, which is what “deep” means formally, or only large in absolute terms?

Primary resource

Charles H. Bennett, “Logical Depth and Physical Complexity” (1988), free PDF and unusually readable. Read Section 1 (pp. 1–7: buried redundancy, cryptic vs. ambitious vs. deep, Ω vs. K₀), then Section 3 through “Examples of Very Deep Objects” (pp. 14–20).
