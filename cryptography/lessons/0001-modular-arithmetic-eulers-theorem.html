Modular Arithmetic & Euler's Theorem

Every public-key cryptosystem this course covers — RSA, Diffie-Hellman, elliptic curves — is built on the same small pile of number theory: arithmetic that wraps around, and one theorem about what happens when you raise a number to a large power inside that wraparound world. This lesson builds that pile from scratch, with every claim backed by a computation you can check by hand.

Congruence: arithmetic that wraps around

Two integers a and b are congruent modulo n, written a ≡ b (mod n), if they leave the same remainder when divided by n — equivalently, if n divides (a − b) exactly. Modular addition, subtraction, and multiplication all work exactly like ordinary arithmetic, then reduce the result mod n:

23 mod 7 = 2        (23 = 3·7 + 2)
5 + 6 mod 7  = 11 mod 7 = 4
5 · 6 mod 7  = 30 mod 7 = 2

The whole point of working "mod n" is that you only ever need to keep track of n possible values (0 through n−1), no matter how large the numbers you started with get — which is exactly the property that makes it possible to do cryptographic arithmetic on 600-digit numbers without the intermediate results exploding in size. Later in this lesson you'll see this taken to its logical extreme.

Modular inverses

In ordinary arithmetic, every nonzero number a has a multiplicative inverse 1/a. Mod n, that's no longer automatic. The modular inverse of a mod n is a number a⁻¹ such that a · a⁻¹ ≡ 1 (mod n) — and it exists if and only if gcd(a, n) = 1, i.e. a and n are coprime (share no common factor bigger than 1).

Why the gcd condition is exact, not just sufficient If d = gcd(a, n) > 1, then every multiple of a mod n is also a multiple of d mod n, so a·x mod n can never land exactly on 1 unless d = 1. Conversely, when gcd(a, n) = 1, the extended Euclidean algorithm constructs integers x, y with a·x + n·y = 1 directly — reduce that equation mod n and a·x ≡ 1 (mod n) falls out, so x is the inverse. This is the same machinery RSA key generation uses to compute the private key.

Worked check: is 4 invertible mod 9? gcd(4, 9) = 1, so yes — and indeed 4 · 7 = 28 = 3·9 + 1 ≡ 1 (mod 9), so 4⁻¹ ≡ 7 (mod 9). Is 3 invertible mod 9? gcd(3, 9) = 3 ≠ 1, so no — and you can check by brute force that 3·x mod 9 only ever lands on {0, 3, 6}, never 1, for any x.

Euler's totient function

Euler's totient function φ(n) counts how many integers in {1, ..., n} are coprime to n — equivalently, by the section above, how many integers mod n actually have a multiplicative inverse. Two facts make it computable without checking every number by hand:

  • If p is prime, every one of 1, ..., p−1 is coprime to p (a prime shares no factors with anything smaller), so φ(p) = p − 1.
  • If p and q are distinct primes, φ(pq) = (p − 1)(q − 1) — this is the specific fact RSA key generation is built on.

Worked example: φ(10). The numbers coprime to 10 in {1,...,10} are {1, 3, 7, 9} — four of them — so φ(10) = 4. Check against the prime-factor formula: 10 = 2·5, so φ(10) = (2−1)(5−1) = 1·4 = 4. Matches.

Euler's theorem

Euler's theorem If gcd(a, n) = 1, then aφ(n) ≡ 1 (mod n).

Raise any number coprime to n to the φ(n)-th power, reduce mod n, and you always land back on 1 — no matter how large a is. This single fact is the engine behind RSA decryption recovering the original message exactly.

Worked example: a = 3, n = 10 φ(10) = 4 from above. 34 = 81 = 8·10 + 1, so 34 mod 10 = 1 — exactly as Euler's theorem predicts. Try a = 7: 74 = 2401 = 240·10 + 1, so 74 mod 10 = 1 as well. It holds for every a coprime to 10, not just one lucky choice.

A second, larger check with a composite modulus that isn't just two small primes multiplied together: n = 91 = 7 · 13, so φ(91) = (7−1)(13−1) = 6·12 = 72. Take a = 5 (gcd(5, 91) = 1). Computing 572 mod 91 directly by repeated squaring (the technique in the next section) gives exactly 1, confirming the theorem on a case too large to check by brute-force multiplication.

Fermat's little theorem: the prime special case

Fermat's little theorem is Euler's theorem restricted to the case where n is prime: since φ(p) = p − 1 for prime p, Euler's theorem becomes ap−1 ≡ 1 (mod p) for any a not divisible by p. It's usually taught first, historically, but it's really just Euler's theorem with the totient function plugged in for a prime modulus.

Worked example: reducing a huge exponent Compute 7222 mod 11 without ever forming a 188-digit number. Since 11 is prime, Fermat gives 710 ≡ 1 (mod 11). Write 222 = 22·10 + 2, so 7222 = (710)22 · 72 ≡ 122 · 72 ≡ 72 (mod 11). And 72 = 49 = 4·11 + 5, so 7222 mod 11 = 5. The exponent 222 collapsed to 222 mod 10 = 2 the moment the modulus's structure was used.

Fast modular exponentiation: square-and-multiply

Cryptography routinely needs ab mod n for b hundreds of digits long. Multiplying a by itself b times is out of the question — but you don't have to. Square-and-multiply computes it in roughly log₂(b) modular multiplications by using the binary expansion of the exponent: scan the exponent's bits left to right, squaring the running result every step and multiplying in an extra factor of a whenever the bit is 1.

Worked example: 413 mod 497 13 in binary is 1101. Track a running result r, starting at 1, processing bits left to right — square every step, multiply by 4 only on a 1-bit: 
bit 1: r = 1² · 4 = 4
bit 1: r = 4² · 4 = 64
bit 0: r = 64² mod 497 = 120        (no multiply — bit is 0)
bit 1: r = 120² mod 497 · 4 = 445
Four squarings and three extra multiplications recovers 413 mod 497 = 445 — versus 12 multiplications for the naive approach, and the gap only widens as the exponent grows. This is the exact technique both RSA encryption/decryption and Diffie-Hellman run under the hood — every "compute ab mod n" in this course is this algorithm, not literal repeated multiplication.
Fast to compute forward, hard to invert Square-and-multiply makes ab mod n cheap to compute when you know a and b. It says nothing about how to go backward — given ab mod n and a, recover b. That's the discrete logarithm problem, and its believed hardness is exactly what lesson 4 builds on.

Practice before next lesson

By hand: compute 3222 mod 11. Don't multiply 3 by itself 222 times — use Fermat's little theorem to reduce the exponent first (11 is prime, so 310 ≡ 1 mod 11), the same way the worked example above reduced 7222 mod 11. You should get 9. This "reduce the exponent mod (p−1) first" move is exactly what makes RSA and Diffie-Hellman practical with real-world key sizes.
