RSA: Key Generation, Encryption & a Full Correctness Proof

Euler's theorem guarantees that aφ(n) ≡ 1 (mod n) whenever gcd(a, n) = 1. RSA turns that single fact into an entire public-key cryptosystem: a scheme where anyone can encrypt a message using a key you publish openly, but only you — holding a second, secret key — can decrypt it. This lesson builds RSA from the ground up and proves, with real numbers, that decryption really does recover the original message.

The idea: two keys, not one

Classical (symmetric) encryption uses one shared secret key for both encrypting and decrypting — which means the two parties need a secure way to agree on that key before they can talk securely at all, a chicken-and-egg problem. Public-key cryptography breaks that circularity: each person publishes a public key that anyone can use to encrypt a message to them, while keeping a mathematically linked private key secret, which alone can decrypt it. RSA — named for Rivest, Shamir, and Adleman, who published it in 1977 — was the first practical realization of this idea, and it works because of a computational asymmetry: multiplying two large primes together is easy, but factoring the product back apart is (believed to be) hard. Lesson 3 examines that hardness claim directly.

Key generation

To generate an RSA key pair:

  1. Choose two distinct large primes p and q. Compute n = p · q — this is the modulus, and it's published as part of the public key.
  2. Compute φ(n) = (p − 1)(q − 1), using the totient product formula from lesson 1. φ(n) is not published — knowing it is equivalent to knowing p and q.
  3. Choose a public exponent e with 1 < e < φ(n) and gcd(e, φ(n)) = 1 — e must have a modular inverse mod φ(n) for the next step to work. e = 65537 is the near-universal choice in practice; small toy examples often use e = 17 or e = 3.
  4. Compute the private exponent d as the modular inverse of e mod φ(n): d ≡ e⁻¹ (mod φ(n)), found with the extended Euclidean algorithm.

The public key is the pair (n, e). The private key is (n, d) — or equivalently just d, since n is already public.

Worked example: p = 61, q = 53 This is the classic small-number pair used in most textbook RSA walkthroughs — small enough to compute by hand, structurally identical to a real 2048-bit key. 
n   = p·q       = 61 · 53        = 3233
φ(n) = (p−1)(q−1) = 60 · 52       = 3120

Choose e = 17.  gcd(17, 3120) = 1, so 17 qualifies.
Solve 17·d ≡ 1 (mod 3120):   d = 2753
Check: 17 · 2753 = 46801 = 15·3120 + 1  →  46801 mod 3120 = 1 ✓
Public key: (n=3233, e=17). Private key: (n=3233, d=2753). Keep p=61 and q=53 (and φ(n)=3120) secret — everything an attacker needs to forge d is right there.

Encryption

To encrypt a message m (an integer with 0 ≤ m < n — real implementations pad and chunk text into integers in this range), the sender who only knows the public key (n, e) computes:

c = m^e mod n

using square-and-multiply, exactly as in lesson 1.

Worked example: encrypting m = 65 Using the public key (n=3233, e=17): c = 6517 mod 3233. Tracing square-and-multiply on the binary expansion of 17 (10001): 
bit 1: r = 1² · 65 mod 3233   = 65
bit 0: r = 65² mod 3233       = 992
bit 0: r = 992² mod 3233      = 1232
bit 0: r = 1232² mod 3233     = 1547
bit 1: r = 1547² mod 3233 · 65 = 2790
Ciphertext: c = 2790. This is the number that actually gets sent — 2790 reveals nothing about 65 without the private key.

Decryption

The holder of the private key (n, d) recovers the message from the ciphertext with the mirror-image computation:

m = c^d mod n
Worked example: decrypting c = 2790 m = 27902753 mod 3233. Squaring 2753 times by hand isn't the point — square-and-multiply again does it in about log₂(2753) ≈ 12 modular multiplications, and the result is exactly m = 65, the original message, recovered exactly.

Why decryption recovers the message: the correctness proof

It's not a coincidence that decryption undoes encryption — it's forced by Euler's theorem. Start from the definitions: c = me mod n, and d was chosen so that e·d ≡ 1 (mod φ(n)), which means e·d = 1 + k·φ(n) for some integer k. Then:

c^d mod n = (m^e)^d mod n = m^(e·d) mod n = m^(1 + k·φ(n)) mod n = m · (m^φ(n))^k mod n

By Euler's theorem, mφ(n) ≡ 1 (mod n) whenever gcd(m, n) = 1 — which holds for essentially every message, since n's only factors are the two large secret primes p and q, and a random m smaller than n is vanishingly unlikely to happen to be a multiple of either. So (mφ(n))k ≡ 1k = 1 (mod n), and the whole expression collapses to:

c^d mod n = m · 1 mod n = m

Decryption recovering the original message isn't a lucky property of the specific numbers above — it's a direct algebraic consequence of e and d being modular inverses mod φ(n), combined with Euler's theorem. Check it against the worked numbers: e·d = 17 · 2753 = 46801 = 1 + 15·3120, so k = 15 — and indeed 27902753 mod 3233 computes out to 65.

The edge case: what if gcd(m, n) ≠ 1? If m happens to be a multiple of p or q (astronomically unlikely for a random message against 300-digit primes, but worth naming), Euler's theorem doesn't directly apply since it requires gcd(m, n) = 1. The proof still goes through using the Chinese Remainder Theorem and Fermat's little theorem applied separately mod p and mod q — the full argument is a short extension of the one above, and is covered in the primary resource below rather than repeated here, since it changes no conclusion.
