Why Factoring Is Hard — and Exactly What Shor's Algorithm Breaks

Lesson 2 named the computational asymmetry RSA rests on: multiplying two large primes is fast, factoring the product back apart is believed to be slow. This lesson makes that precise — what "slow" actually means classically, and then the exact mechanism (not the pop-science version) by which a quantum computer changes the answer. This is the lesson that connects directly back to Quantum Computing's still-locked Shor's algorithm material.

Classical factoring: no known shortcut

Given n = p·q for two large unknown primes, the obvious algorithm — trial division by every integer up to √n — takes time exponential in the number of digits of n, since √n itself has roughly half as many digits as n but is still astronomically large. Decades of number theory have produced much better classical algorithms: Pollard's rho, the quadratic sieve, and the current champion, the general number field sieve (GNFS). GNFS is sub-exponential — faster than exponential, but still growing faster than any polynomial in the number of digits of n:

GNFS running time ≈ exp( c · (ln n)^(1/3) · (ln ln n)^(2/3) )     for a constant c ≈ 1.9

No classical algorithm is known that factors n in time polynomial in its number of digits — and after roughly fifty years of concerted cryptanalytic effort against exactly this problem, most cryptographers treat that absence as strong (though not proven) evidence that no such algorithm exists. RSA's security is a direct bet on that absence continuing to hold classically.

"Believed hard," not "proven hard" Nobody has proven factoring is classically intractable — that would resolve deep open questions in complexity theory (factoring sits inside NP ∩ co-NP, and isn't known or believed to be NP-complete). RSA's security is a cryptographic assumption, calibrated against the best known attacks and how key sizes have had to grow over time to stay ahead of them, not a mathematical certainty.

Breaking RSA vs. factoring n

Strictly, the problem an attacker needs to solve is the RSA problem: given (n, e, c), recover m, without necessarily factoring n. Every known efficient way to solve the RSA problem goes through factoring n first (recover p and q, then φ(n), then d, exactly reversing key generation) — but it remains a technically open question whether some other shortcut could break RSA without factoring. In practice, "RSA is secure" and "factoring is hard" are treated as the same assumption, because no attack exploiting the gap between them has ever been found.

Turning factoring into period-finding

Shor's algorithm doesn't factor n directly. It reduces factoring to a different problem — order-finding — using number theory that is entirely classical, and then solves that problem efficiently with a quantum subroutine. It helps to see the classical reduction first, since it's a real algorithm you can run by hand on small numbers.

Pick a random a with 1 < a < n and gcd(a, n) = 1 (if gcd(a, n) ≠ 1, you've already found a factor by luck — done). The sequence a mod n, a² mod n, a³ mod n, ... is eventually periodic; its period r is called the order of a mod n — the smallest r with ar ≡ 1 (mod n). If r happens to be even, and ar/2 ≢ −1 (mod n), then:

gcd(a^(r/2) − 1, n)  and  gcd(a^(r/2) + 1, n)

are both nontrivial factors of n, computable instantly with the (classical, fast) Euclidean algorithm once you know r.

Worked example: factoring n = 15 Pick a = 7 (gcd(7, 15) = 1). Compute powers of 7 mod 15 until they cycle back to 1: 
7^1 mod 15 = 7
7^2 mod 15 = 49 mod 15 = 4
7^3 mod 15 = 28 mod 15 = 13
7^4 mod 15 = 91 mod 15 = 1     ← back to 1: order r = 4
r = 4 is even. Compute ar/2 = 7² mod 15 = 4, and check it isn't −1 ≡ 14 (mod 15) — it isn't. Then: 
gcd(4 − 1, 15) = gcd(3, 15) = 3
gcd(4 + 1, 15) = gcd(5, 15) = 5
3 and 5 — exactly the two prime factors of 15 — fall out of nothing but the order of 7 mod 15 and two gcd computations. This is the actual example most textbooks (and this course) use to demonstrate Shor's algorithm, precisely because n=15 is small enough to find the order by brute-force listing, the way you'd have to without a quantum computer for any realistically-sized n.

Everything above — choosing a, the two gcd computations, even checking whether r is even — is fast, classical arithmetic. The only expensive step, classically, is finding the order r itself: for a real RSA-sized n, the sequence a, a², a³, ... doesn't repeat until roughly n steps in the worst case, which is exactly as infeasible as factoring n directly by brute force. Order-finding is the one step Shor's algorithm accelerates with a quantum computer — nothing else in the reduction above needs to change.

The quantum part: order-finding via phase estimation

Order-finding turns out to be exactly the problem phase estimation solves. Define the unitary U|x⟩ = |a·x mod n⟩ (multiplication by a, mod n, is reversible when gcd(a,n)=1, so this really is a valid unitary). U's eigenvalues turn out to be e2πik/r for k = 0, ..., r−1 — the order r you're looking for is baked directly into U's eigenvalue structure. Run phase estimation against U starting from an appropriate eigenstate, and it reads out one of these eigenvalues' phase k/r to high precision — which, combined with the classical continued-fractions algorithm, reveals r itself with high probability.

The reason this needs a quantum computer at all is the same reason lesson 6 of Quantum Computing built the QFT in the first place: the control register phase estimation produces is exactly the periodic, phase-structured state (1/√2^t) Σ_k e^(2πiφk)|k⟩ the QFT is built to decode — decoding periodicity out of a superposition is precisely the QFT's specialty, and no known classical algorithm extracts that same periodicity from ax mod n without effectively checking exponentially many values of x.

What this lesson is not claiming This is a conceptual-level account, not a circuit-level one: it names order-finding as the bottleneck, and phase estimation plus the QFT as the tool that solves it in polynomial time on a fault-tolerant quantum computer — matching what Quantum Computing lesson 6 already built. It does not derive the specific controlled-U2ʲ circuit for modular multiplication, nor the continued-fractions step that converts a phase estimate into an exact order r — both are real engineering, covered in the primary resource below, and in Quantum Computing's own upcoming Shor's algorithm lesson.

Put together: Shor's algorithm is classical reduction (factoring → order-finding, entirely number theory, done above by hand) plus quantum order-finding (phase estimation + QFT, built entirely from machinery Quantum Computing lessons 1–6 already cover). Nothing about it "tries every factor at once" — it turns factoring into a period, and reads the period off with interference, the same non-magical mechanism behind every algorithm in that course.

Practice before next lesson

By hand: factor n = 21 using the same classical reduction, with a = 2. Compute powers of 2 mod 21 until you find the order r, confirm it's even, then compute gcd(2r/2 − 1, 21) and gcd(2r/2 + 1, 21). You should recover 3 and 7. This is the entire classical half of Shor's algorithm — the only thing a quantum computer changes is how fast you can find r when n has hundreds of digits instead of two.
