Recursion & Backtracking

When an interviewer says “return all” (every subset, every ordering, every valid board), the hidden question is: can you walk an exponential search space without corrupting shared state, and can you say how big it is before you write a line? Lesson 1 listed O(2ⁿ) as “naive recursion” without saying why. Here you get the why, then one Rust template (choose, explore, unchoose) for subsets, permutations and combination sums. It is the tree recursion you already know, run as a DFS over a tree that you never build.

Recursion trees: count nodes, not depth

Draw one node per call, and label it with the work that call does excluding its recursive calls. The running time is the sum over all nodes (Erickson, ch. 1, “Recursion Trees”). With branching factor b ≥ 2 and depth d there are up to bᵈ leaves, and at most (bᵈ⁺¹ − 1)/(b − 1) = O(bᵈ) nodes in all.

// b = 2 calls per node, depth n
fn fib(n: u64) -> u64 {
    if n < 2 { return n; }
    fib(n - 1) + fib(n - 2)
}

// b = 1 call per node, depth ≈ log₂ n
fn pow(x: f64, n: u32) -> f64 {
    if n == 0 { return 1.0; }
    let half = pow(x, n / 2);
    if n % 2 == 0 { half * half } else { half * half * x }
}
fibO(φⁿ) time, O(n) space
powO(log n) time, O(log n) space

Two calls per node over depth n is the O(2ⁿ) row of the Big-O table. The exact count is 2·F(n+1) − 1 calls, which grows like φⁿ ≈ 1.618ⁿ (Erickson, ch. 3). That is below 2ⁿ because the n − 2 side is shallower. One call on half the input is a single path of about log₂ n nodes, the same as square-and-multiply. Fib’s tree also recomputes fib(n − 2) twice and fib(n − 3) three times. Those are overlapping subproblems, the starting point of dynamic programming. To write recursion, trust the subcall, which Erickson calls the “Recursion Fairy”, and get only your own level right.

Common interview trap “It recurses n deep, so it’s O(n).” Depth bounds space. Time counts nodes, and with b calls per node the bottom level alone has bᵈ of them. Say both numbers.

Call-stack space: depth is memory

Each pending call holds a stack frame until it returns, and only one root-to-leaf path is live at a time, so extra space is O(depth). That is the “space counts extra memory” trap again. Recursion is never O(1) space without guaranteed tail calls (Tech Interview Handbook). Rust gives “no guarantees” that a call becomes a tail call. Its explicit become is still an incomplete, nightly-only feature as of October 2026 (std docs). As of April 2026, its implementers hope to stabilize it in 2027 (Trifecta Tech).

A spawned thread currently gets a 2 MiB stack by default on all Tier-1 platforms (as of Rust 1.99, October 2026; the docs say this may change). The main thread’s stack size “is not determined by Rust” (std::thread). A recursive flood fill over an all-land 1000 × 1000 grid goes 10⁶ frames deep. On a default spawned thread (rustc 1.97, -O) it aborts with “has overflowed its stack”. The interview fix is an explicit Vec stack, as in iterative grid walks. The quick patch is thread::Builder::new().stack_size(512 << 20), which completes the same fill.

Backtracking: choose, explore, unchoose

Backtracking builds a solution one decision at a time and recursively evaluates every alternative for the next decision (Erickson, ch. 2). Each node is a partial solution and each edge is one choice. You mutate one shared path: choose (push), explore (recurse), unchoose (pop). The pop restores path exactly as the parent left it, so siblings never see each other’s choices. It is not blind brute force, because it can abandon a partial solution the moment it can’t succeed (CPH §5.3–5.4).

Subsets: one node per answer

fn subsets(nums: &[i32]) -> Vec<Vec<i32>> {
    fn bt(start: usize, nums: &[i32], path: &mut Vec<i32>, out: &mut Vec<Vec<i32>>) {
        out.push(path.clone());          // record: every node is a subset
        for i in start..nums.len() {
            path.push(nums[i]);          // choose
            bt(i + 1, nums, path, out);  // explore
            path.pop();                  // unchoose
        }
    }
    let mut out = Vec::new();
    bt(0, nums, &mut Vec::new(), &mut out);
    out
}
// O(n·2ⁿ) time: 2ⁿ subsets, each cloned in O(n). O(n) extra space: path + n + 1 frames.
// Can you do better? Not asymptotically: the output alone holds n·2ⁿ⁻¹ numbers.
TimeO(n·2ⁿ)SpaceO(n) extra

Each element is in or out, which gives 2ⁿ subsets. CPH §5.1 draws this as an include/exclude tree. The loop form makes one call per subset, so it records at every node. In Rust, out.push(path) fails with “expected Vec<i32>, found &mut Vec<i32>”, where garbage-collected languages would silently store one aliased list. The clone is the snapshot, and also the n in n·2ⁿ. One-line alternative: loop mask in 0..1u32 << n and read the bits, as a truth table does for its 2ⁿ rows.

Permutations: n choices, then n − 1, …

fn bt(nums: &[i32], used: &mut [bool], path: &mut Vec<i32>, out: &mut Vec<Vec<i32>>) {
    if path.len() == nums.len() { out.push(path.clone()); return; }  // record at leaves
    for i in 0..nums.len() {
        if used[i] { continue; }
        used[i] = true; path.push(nums[i]);   // choose
        bt(nums, used, path, out);             // explore
        path.pop(); used[i] = false;           // unchoose
    }
}
// O(n·n!) time: n! leaves, each cloned in O(n). O(n) extra space.
// Can you do better? Not asymptotically: the output alone holds n·n! numbers.
TimeO(n·n!)SpaceO(n) extra

Order matters, so every unused element is a candidate at every level. That gives n! leaves and about e·n! nodes. used is a seen-set over indices, and unchoose must clear it. You can drop used by swapping nums[start] with each nums[i], recursing on start + 1, then swapping back. Combinations reuse the subsets template, but record and return when path.len() == k. Combination Sum allows reuse, so it recurses with i instead of i + 1. That one index is what controls reuse.

Output cost is answers × length. Anything that returns every answer must write that much, so it answers “Can you do better?”.

Why interviewers care Constraints leak the intended complexity. For a one-second limit, CPH’s rule of thumb is that n ≤ 10 suggests O(n!) and n ≤ 20 suggests O(2ⁿ) (§2.3). A “return all” prompt with n ≤ 20 says exponential is expected. What gets graded is a clean template, no leaked state, and an honest bound stated up front.
“There are 2ⁿ subsets and I copy each, so O(n·2ⁿ) time. Extra space is O(n) for the path and the n + 1 frames, not counting output. The output alone has n·2ⁿ⁻¹ numbers, so nothing does better asymptotically. If you only need the count, the subproblems repeat and I’d switch to DP.”

Pruning: abandon a branch at the first sign of failure

  
Pruning notices as early as possible that a partial solution can’t be completed (CPH §5.4). The first common move is sort, then break: once a sorted candidate exceeds what remains, every later one does too.


// c is sorted (sort_unstable) before the first call: bt(0, target, &c, ..)
fn bt(start: usize, remain: i32, c: &[i32], path: &mut Vec<i32>, out: &mut Vec<Vec<i32>>) {
    if remain == 0 { out.push(path.clone()); return; }
    for i in start..c.len() {
        if c[i] > remain { break; }          // prune: sorted, so the rest are too big
        path.push(c[i]);
        bt(i, remain - c[i], c, path, out);  // i, not i + 1: reuse allowed
        path.pop();
    }
}
// candidates [2, 3, 6, 7], target 7  →  [[2, 2, 3], [7]]

  
TimeO((T/m)·n^(T/m)) worst caseSpaceO(T/m) depth

  
With n candidates, target T and smallest candidate m, each level subtracts at least m, so the depth is at most T/m and each node has at most n children: O(n^(T/m)) nodes, plus O(T/m) to clone each answer. The break leaves that worst-case bound alone, but it removes every branch that overshoots.

  
The second move is constraint flags. N-Queens places one queen per row and keeps an O(1) flag per column and per diagonal (row + col and row − col are constant along one). For n = 8, checking only full boards tests 8⁸ ≈ 1.7 × 10⁷ leaves. With flags, the search visits 2,057 nodes and finds all 92 solutions (both counts are from running the code). In CPH, four simple prunes on a grid-path count cut 76 billion calls to 69 million, nearly 1000× faster.


  

    Common interview trap
    Claiming that pruning changes the bound. It rarely improves the worst case, and N-Queens is still exponential. What shrinks is the constant and the typical case. Say so: “Worst case is still exponential; the break cuts every branch that overshoots.”
  


  
Skipping duplicates

  
With repeats like [1, 2, 2], two siblings that pick equal values grow identical subtrees. Sort first, then in the loop: if i > start && nums[i] == nums[i - 1] { continue; }. That skips an equal value at the same depth. It has to be i > start and not i > 0, because i == start is the first candidate of a new frame, and that is how [2, 2] gets built. On [1, 2, 2] the result is 6 subsets instead of 8 with repeats. Permutations with repeats use the same idea: after sorting, skip nums[i] when i > 0, it equals nums[i - 1] and !used[i - 1] (an equal twin must be placed in order). There i > 0 is right, because the loop starts at 0 in every frame.

Practice before next lesson

  
Work in Rust from a blank file, with 20 minutes per problem. State the answer count and output cost aloud before typing. The problems are Subsets, Permutations, Combinations, Combination Sum, Subsets II, Letter Combinations of a Phone Number and Generate Parentheses, most of them listed on the Tech Interview Handbook recursion cheatsheet. As a stretch, do N-Queens with column and diagonal flags. Then write a count-only Combination Sum and notice the repeated subproblems. That is where dynamic programming starts.
