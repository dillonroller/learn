Computability Theory & Turing Degrees: How Undecidable Is It?

Three earlier lessons made promises that this one keeps. Lesson 9 said first-order logic is "complete but not decidable" and left the asymmetry unexplained: proof search finds every valid sentence but may run forever on the rest. Lesson 11 called the halting problem a "familiar cousin" of Gödel's proof and never proved it. Lesson 15 leaned on "Church–Turing material" to claim that proof-checking is arithmetic. This lesson proves the halting theorem, then turns "undecidable" from a label into a measurement. The tangible win: given a yes/no question about programs or arithmetic, you write it as quantifiers over a decidable core, count the alternations, and read off how undecidable it is.

The halting problem, actually proved

(Answers: a procedure that always terminates with the right yes/no; it fed a formula its own code.) Any programming language serves as the model of computation; the Church–Turing thesis says nothing is lost by that choice. It is a thesis about the informal word "computable", not a theorem. Programs are strings and strings are numbers (Gödel numbering again), so a program can take a program, even itself, as input.

Theorem (Turing, 1936, in modern form): halting is undecidable No program halts(src, input) always terminates and returns true exactly when the program src, run on input, eventually halts.

Proof. Suppose someone hands you one. Add a few lines:

fn halts(src: &str, input: &str) -> bool { /* assumed: always returns, always right */ }

fn contrary(src: &str) {
    if halts(src, src) {
        loop {}   // predicted to halt? then run forever
    }             // predicted to loop? then return at once
}

Let C be the complete source of contrary (with halts pasted in) and ask what contrary(C) does. If halts(C, C) says true, contrary(C) loops forever, so halts was wrong. If it says false, contrary(C) returns at once: wrong again. Every candidate decider fails on the input built from it. ∎ Since contrary only asks halts(src, src), even the self-halting question ("does e halt on its own code?") is undecidable.

The promise, kept literally This is lesson 11's "familiar cousin" in the promised shape: an object engineered to contradict whatever the solver says about it. The self-application halts(src, src) is lesson 15's diag, code fed its own code, as in a quine. G says "I am unprovable"; contrary(C) does the opposite of whatever you predict; the uncomputability of K(x) is a third family member. Nothing is contradictory except the assumed decider.
What the theorem does not say Not that a particular program's behaviour is unknowable: every instance has a definite answer, and many are settled one by one. BB(5) = 47,176,870 was pinned down in 2024 by settling every five-state, two-symbol Turing machine, stubborn holdouts included, checked in the Coq proof assistant (Quanta). Not about patience: "halts within 10⁶ steps" is decidable; run it and look. Not about hardware: a Turing machine can simulate a quantum computer, so quantum hardware changes cost, never possibility (Wikipedia; SEP). Cost is complexity theory's question, where BQP lives. What the theorem rules out is one uniform program that is right on every input.

Half a decider: computably enumerable sets

Halt is half-decidable: if e halts on n, running it confirms so in finite time. A set is computably enumerable (c.e.) when some program halts on exactly its members: "yes" is always eventually confirmed, "no" may never be. Equivalently, membership is "a finite witness exists" for a decidable check. For Halt the witness is a step count s and the check is Step(e, n, s): "run e on n for s steps; has it stopped?" Listing every yes-instance takes dovetailing, which the Ω lesson already walked through.

Decidable ⟺ c.e. and co-c.e. (Post, 1944) If A and its complement are both c.e., run their confirmers side by side: every n is on one side, so one search stops and says which. A decider confirms both sides, so the converse is free. Corollary: ¬Halt is not c.e., or Halt would be decidable (SEP §3.3).

That is lesson 9's asymmetry, named. By completeness every valid sentence has a proof, and proof-checking is mechanical, so FOL validity is c.e. If invalidity were c.e. too, validity would be decidable. The next section shows it is not, so no procedure, however clever its search, can always know when to give up.

Hilbert's third goal fails: the Entscheidungsproblem

Hilbert's program wanted a mechanical procedure to settle any statement; the core case, posed by Hilbert and Ackermann (1928), is the Entscheidungsproblem: decide whether a first-order sentence is valid. Church and Turing (1936) showed there is no such procedure. From a program e and input n you can mechanically write a sentence φe,n describing the computation, valid iff e halts on n (SEP §1.7). A validity decider would be a halting decider. So validity is c.e. but undecidable, in pure logic, before any arithmetic enters.

Incompleteness, re-derived from halting Let T be a sound theory whose theorems a program can list (PA qualifies), and suppose T proved every true "program e never halts on input e", that is, every true ∀s ¬Step(e, e, s). Then decide self-halting: run e on e while listing T's theorems for "e never halts". Soundness makes exactly one search stop. That is impossible, so T misses some true "e never halts": Gödel I for sound theories, with the diagonal argument spent once, inside the halting proof (Smith §43.4; Open Logic §6.14 weakens soundness to ω-consistency). Lesson 15's route needs only consistency to make G unprovable, and names the sentence; the halting route can be tightened to do the same, naming a Π₁ sentence of its own (Smith §43.5).
The bridge to intuitionism: what LEM costs PA proves ∀e (Halt(e) ∨ ¬Halt(e)) in one line, as an instance of LEM. Under BHK, a proof must say, uniformly in e, which disjunct holds. Heyting Arithmetic makes that exact via the Church–Kleene rule: if HA proves ∀x ∃y A(x, y), a computable function produces the y (SEP §4.2), and a disjunction is an ∃ over a 0/1 tag. An HA proof would be a halting decider, so HA cannot prove what PA proves trivially.

Measuring hardness: oracles and reductions

To compare undecidable problems, pretend one is handed to you as a black box. An oracle machine (Turing, 1939) is an ordinary program that may also call oracle_b(n) -> bool, which answers "is n in B?" in one step. A ≤T B (Turing reducible) means some oracle program decides A given B's oracle. A ≤m B (many-one) is the special case of one query with the answer passed through unchanged: a computable f with n ∈ A ⟺ f(n) ∈ B (SEP §3.5).

// ¬Halt ≤_T Halt: one query, answer flipped
fn never_halts(e: u64, oracle_halt: impl Fn(u64) -> bool) -> bool {
    !oracle_halt(e)
}

(e, n) ↦ φe,n gives Halt ≤m Validity; "search for a proof of φ, halt if found" gives Validity ≤m Halt. Equally hard. But never_halts flips the answer, which ≤m forbids, and rightly: ≤m preserves being c.e., so ¬Halt ≰m Halt. Keep that asymmetry; it returns as Σ versus Π.

Direction is everything To prove a new problem B undecidable, reduce a known-hard problem to B: Halt ≤ B, "if I could solve B, I could solve halting." Showing B ≤ Halt proves only that B is no harder than halting.

Turing degrees: 0 and 0′

A ≡T B (Turing equivalent) when each reduces to the other. A Turing degree is an equivalence class under ≡T: a bucket of problems carrying exactly the same information. 0 is the bucket of decidable sets. 0′ is the degree of Halt, which also holds ¬Halt (flip the oracle), FOL validity (the two reductions above), and Chaitin's Ω, whose bits encode halting and which is Turing equivalent to it. Halt is the hardest c.e. set: every c.e. set is ≤m Halt (SEP §3.5.1).

The jump: no hardest problem

Give every program a Halt oracle. These oracle programs have a halting problem of their own. In general the jump A′ is the halting problem for programs with an A-oracle; so 0′ is the jump of the decidable sets, and 0″ is the jump of Halt.

Theorem: A <T A′ for every A A′ is not computable from A: rerun the halting proof with every program allowed to call oracle_a. If an A-oracle program halts_with(src, input, oracle_a) decided A′, then contrary_with ("if halts_with(src, src, oracle_a), loop forever") is a legal A-oracle program, and its own source gives the same contradiction line for line; the proof never cared what programs may call. A ≤T A′: "ask the oracle whether n ∈ A; halt if yes, loop if no" halts exactly when n ∈ A, so one A′ query answers it.

So 0 < 0′ < 0″ < 0‴ < … with no top (SEP §3.5.2). A halting oracle does not decide everything: its own halting problem is out of reach, as in Aaronson's tower of "super" and "super duper" machines. You have seen the shape: add G as an axiom, get G′ one level up. Patch in the answer and the diagonal construction runs again on the patched system.

The degrees are not a single ladder, though: Kleene and Post (1954) built incomparable degrees, and Friedberg (1957) and Muchnik (1956) built c.e. sets whose degrees lie strictly between 0 and 0′, solving "Post's problem" with the priority method (same SEP section). The jump sequence is a spine through a messier structure; we only need the spine.

The practical tool: count the quantifiers

The arithmetical hierarchy reads hardness off a definition. Start from a decidable core: Step(e, n, s), Prime(p), or lesson 15's Proof(x, y), the "finite, mechanical, terminating" check. A bounded quantifier (∃x<t, ∀x<t) is a for-loop, so it stays inside the core. Then stack unbounded quantifiers in front. Σₙ: n alternating blocks starting with ∃. Πₙ: the same starting with ∀. Δₙ: expressible both ways; Δ₁ turns out to be exactly the decidable sets. (Officially the core may use only bounded quantifiers. A decidable relation can always be rewritten with one extra unbounded quantifier of either type, so pick the type of the innermost block and merge: levels ≥ 1 come out the same.) The procedure:

  1. Write the claim as quantifiers over a decidable core, pushing ¬ inward first (it swaps ∃ and ∀).
  2. Drop bounded quantifiers: they are loops inside the core.
  3. Merge adjacent same-type quantifiers: ∃n ∃s is one ∃k, with k coding the pair ⟨n, s⟩.
  4. Count the blocks. First block ∃ gives Σ; ∀ gives Π.
Halt(e)    ∃s Step(e,0,s)        Σ₁   // e halts on input 0
¬Halt(e)   ∀s ¬Step(e,0,s)       Π₁
Prov(y)    ∃x Proof(x,y)         Σ₁
Con(PA)    ∀x ¬Proof(x,⌜⊥⌝)      Π₁
G          ∀x ¬Proof(x,⌜G⌝)      Π₁
TOT(e)     ∀n ∃s Step(e,n,s)     Π₂   // halts on every input

Because G ↔ ¬Prov(⌜G⌝), Gödel's unprovable truth is Π₁, as is Con(PA): the same shape as the "e never halts" sentences above. A count is an upper bound, since a cleverer formula might sit lower. It is exact when the problem is complete for its level (every problem there reduces to it): Halt is Σ₁-complete, ¬Halt Π₁-complete, TOT Π₂-complete (SEP §3.6.1). Swap TOT's quantifiers and you get lesson 7's quantifier-order trap: ∃s ∀n Step(e,n,s) claims one step bound for every input, a different claim entirely.

Classify problems and formulas, not lone facts A problem with an input (e, φ) is a set, and its level is a real invariant. A single sentence such as Goldbach's conjecture has no input: as a set it is trivially decidable, since one of the two constant programs is right, though nobody knows which. For a lone sentence, classify the formula that states it: its level says what kind of evidence could settle it.

Post's theorem: quantifiers count jumps

Post's theorem For every n ≥ 0, a set is Σₙ₊₁ exactly when it is c.e. relative to an oracle for 0⁽ⁿ⁾, and Δₙ₊₁ exactly when it is computable from 0⁽ⁿ⁾. For n ≥ 1, the n-fold jump of ∅ (Halt, when n = 1) is Σₙ-complete, and the levels never collapse (SEP §3.6.1, Thms 3.10–3.11).

We prove only n = 0. If A is defined by ∃s R(n, s) with R decidable, "try s = 0, 1, 2, … until R holds" halts exactly on A, so A is c.e. Conversely, if program e halts exactly on A, then n ∈ A ⟺ ∃s Step(e, n, s), a Σ₁ definition. With Post's 1944 result, Δ₁ = decidable follows. The next level shows the pattern: in TOT's ∀n ∃s Step(e, n, s), a Halt oracle answers the whole inner ∃s in one query, leaving a single ∀, a Π₁ question relative to 0′. Each quantifier block costs one jump.

The complete problems at Σₙ and Πₙ are complements, so they share the degree 0⁽ⁿ⁾. What separates them is which answer a finite witness settles. A halting run confirms a Σ₁ claim ("e halts"); one counterexample refutes a Π₁ claim ("e never halts", "PA is consistent"); a ∀∃ claim like "this service always eventually replies" is in general neither confirmed nor refuted by any finite log. That is the payoff for evaluating arguments: before debating whether a claim is true, ask what shape of evidence could ever settle it.

Try it: place the problem on the ladder

Write the quantifier prefix in your head, drop bounded quantifiers, merge same-type neighbours, then pick the lowest level that fits; for a lone sentence, classify its formula, as the callout above says. Feedback reveals the formula. Step(e, n, s) is "has e, on input n, halted by step s?"

Now read the answers through Post's theorem: the complete problems at Σ₁ and Π₁ (halting, validity, never-halting) sit at degree 0′; those at Σ₂ and Π₂ (finitely many, infinitely many, TOT) sit at 0″, strictly harder by the jump theorem.
