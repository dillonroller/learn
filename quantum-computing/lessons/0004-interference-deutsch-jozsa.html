Quantum Interference & the Deutsch-Jozsa Algorithm

This is the lesson the first three were building toward. It corrects the single most common misconception about quantum computing head-on, names the actual mechanism behind every real speedup, and then proves it with the first quantum algorithm ever shown to beat classical computers — worked out by hand, completely, for the simplest case.

Not "trying every answer at once"

The popular claim goes: a quantum computer holds 2ⁿ amplitudes at once, so it "checks all 2ⁿ possible answers in parallel." Lesson 2 already flagged the problem: you can prepare all those amplitudes, but the Born rule only ever hands you one measurement outcome, with a probability equal to that outcome's amplitude squared. If a "correct answer" is hiding among 2ⁿ equally-weighted terms, measuring gives it to you with probability 1/2ⁿ — vanishingly small, no better than guessing. Superposition alone buys you nothing.

What actually buys you something is interference. Amplitudes are complex numbers, and when a computation has more than one path to the same final basis state, those paths' amplitudes add before you square them:

Two paths to the same state, amplitude a and amplitude b:
  constructive:  a + b  can be LARGER than either alone     (same sign / phase)
  destructive:   a + b  can be SMALLER, even exactly 0       (opposite sign / phase)

A quantum algorithm's entire design is about engineering the phases of every computational path so that paths leading to wrong answers cancel to zero, and paths leading to the right answer reinforce. That's the actual mechanism — not "parallel guessing," but "guaranteed cancellation of everything except the answer." The rest of this lesson builds the simplest possible example of that trick from scratch.

Oracles: querying a function as a gate

Many quantum algorithms are phrased in terms of an oracle — a black-box unitary that computes some function f without you knowing its internal wiring, so you can reason about how many times you need to call it, independent of how it's built inside. Because f might not be reversible (e.g. f could map two different inputs to the same output — exactly the AND-gate problem from lesson 3), the standard construction uses an extra output register and XOR, the same ancilla-bit trick that made Toffoli work:

O_f : |x⟩|y⟩  →  |x⟩|y ⊕ f(x)⟩

This is always reversible regardless of whether f itself is — applying O_f twice returns y to its original value, since XOR-ing f(x) in twice cancels out. O_f is how you "call" f inside a quantum circuit.

Phase kickback: the trick that makes it all work

Here's the move that turns a black-box function into something interference can use. Instead of putting a definite value in the target register y, put it in |−⟩ = (|0⟩−|1⟩)/√2:

Deriving phase kickback If f(x)=0: y ⊕ 0 = y, so |−⟩ is untouched: O_f|x⟩|−⟩ = |x⟩|−⟩.
If f(x)=1: y ⊕ 1 swaps 0 and 1 in y's label, which turns (|0⟩−|1⟩)/√2 into (|1⟩−|0⟩)/√2 = −|−⟩. So: O_f|x⟩|−⟩ = −|x⟩|−⟩.

Both cases combine into one formula: O_f|x⟩|−⟩ = (−1)f(x) |x⟩|−⟩.

Look closely at what happened: the target register |−⟩ never changed its label at all — only a phase appeared, and it attached itself to the x register instead. The function's output got "kicked back" onto the input register as a sign. This is exactly the raw material interference needs: f(x) is now encoded as a phase sitting on |x⟩, ready to be cancelled or reinforced against other |x⟩ terms by a later Hadamard.

The Deutsch-Jozsa problem

You're given oracle access to f: {0,1}ⁿ → {0,1}, promised to be one of exactly two kinds:

  • Constant — f outputs the same value for every input.
  • Balanced — f outputs 0 for exactly half of all inputs and 1 for the other half.

Which kind is it? Classically, in the worst case, a deterministic algorithm must query f up to 2n−1+1 times before it can be certain — check just over half the inputs, and if they're all equal you still can't rule out "balanced, and I haven't found the differing half yet." The quantum algorithm below answers with 100% certainty using the oracle exactly once, for any n.

Working the n=1 case completely

This is small enough to carry every amplitude by hand — this is Deutsch's original 1985 algorithm, the n=1 special case of Deutsch-Jozsa. Circuit: two qubits, prepared |0⟩ and |1⟩, Hadamard both, apply the oracle, Hadamard the first qubit, measure it.

q0: |0⟩──[H]──●O_f●──[H]──(measure)
q1: |1⟩──[H]──●O_f●───────────────
Step by step Start: |0⟩|1⟩
After H on both: (|0⟩+|1⟩)/√2 ⊗ (|0⟩−|1⟩)/√2 — note the second register is now exactly |−⟩.
After O_f (phase kickback on each term): [(−1)^f(0)|0⟩ + (−1)^f(1)|1⟩]/√2 ⊗ |−⟩
After H on q0 — using H|0⟩=(|0⟩+|1⟩)/√2 and H|1⟩=(|0⟩−|1⟩)/√2 from lesson 1:
  • If f is constant (f(0)=f(1)): the bracket is ±(|0⟩+|1⟩)/√2. Applying H gives exactly ±|0⟩ — measuring q0 gives 0, with certainty.
  • If f is balanced (f(0)≠f(1)): the bracket is ±(|0⟩−|1⟩)/√2. Applying H gives exactly ±|1⟩ — measuring q0 gives 1, with certainty.

That's the whole mechanism laid bare: the second Hadamard is where interference actually happens — it's the step where the four possible (f(0), f(1)) phase patterns either reinforce onto |0⟩ or reinforce onto |1⟩, with zero probability of landing anywhere else. One oracle call, one measurement, a certain answer.

General n works identically in spirit: Hadamard all n input qubits plus the target, apply O_f once, Hadamard the n input qubits again, and measure them. All-zeros iff f is constant — the algorithm is genuinely n-query-vs-1-query exponential, not just a two-input special case.

Keep this in perspective Constant-vs-balanced is an artificial promise nobody needs solved in practice — Deutsch-Jozsa isn't useful the way Grover's or Shor's are. Its importance is that it was the first rigorous proof that a quantum algorithm can beat every possible classical deterministic algorithm on some problem — proof the exponential speedup you'll see in later lessons isn't just a hope, before those later results made it practically consequential.
