Shor's Algorithm & Breaking RSA

Lesson 6's practice drilled phase estimation (t control qubits, controlled-U2ʲ, inverse QFT), the subroutine Shor's algorithm reuses. Cryptography gave you the classical half: factoring N reduces to finding the order r of a random a mod N, and gcd(a^(r/2) ± 1, N) then gives the factors. This lesson builds the missing middle: the circuit that finds r, the interference that makes it work, and the continued-fraction step that turns one measured number into r. The win: given a measured y, you finish the factoring by hand.

classical   pick a with gcd(a, N) = 1; precompute a^(2^j) mod N
quantum     order-finding circuit  →  one measured integer y
classical   continued fractions on y/Q  →  candidate r; check a^r ≡ 1
classical   gcd(a^(r/2) − 1, N) and gcd(a^(r/2) + 1, N)

The picture first: a comb, and interference reads its spacing

Put a t-qubit counting register into the uniform superposition over x = 0, …, Q−1 (Q = 2ᵗ), then compute the function f(x) = ax mod N into a second register:

(1/√Q) Σ_x |x⟩ |a^x mod N⟩

f repeats with period r, the order of a. Imagine measuring the second register (whether you do changes nothing about the first register's statistics). You see some as, and the first register collapses to a comb |s⟩ + |s+r⟩ + |s+2r⟩ + …: teeth spaced r apart, random offset s. Measuring the comb directly returns a random tooth, which is useless. The inverse QFT instead maps a comb of spacing r to a comb of spacing Q/r, and the offset s becomes a phase that drops out of the probabilities. That is lesson 6's promise, with real numbers.

Worked example: N = 15, a = 7, t = 3 (Q = 8) Powers 7x mod 15 for x = 0…7 are 1, 7, 4, 13, 1, 7, 4, 13, so r = 4. Say the second register shows 4. The counting register is then (|2⟩ + |6⟩)/√2. Apply QFT⁻¹ (amplitude e−2πixy/8/√8 from |x⟩ to |y⟩): 
amp(y) = (1/√2)(1/√8) [ e^(−2πi·2y/8) + e^(−2πi·6y/8) ]
       = (1/4) e^(−iπy/2) [ 1 + (−1)^y ]

y odd   →  1 + (−1) = 0             probability 0
y even  →  |amp| = 2/4 = 1/2        probability 1/4   (y = 0, 2, 4, 6)
Every outcome is a multiple of Q/r = 2, whatever the second register showed. The odd outcomes are not “rejected guesses”: two paths of opposite phase cancel exactly.

Q = 8 is a toy that works only because r = 4 divides 8. The real algorithm takes Q = 2ᵗ with N² < Q ≤ 2N² (t ≈ 2n for an n-bit N), and then r usually does not divide Q. The peaks are no longer exact, but they stay sharp: with probability at least 4/π² ≈ 0.405 the outcome y lands within 1/2 of some c·Q/r (de Wolf, §5.3). The circuit: phase estimation on multiplication by a

How do you compute |x⟩|ax mod N⟩? Define U_a|w⟩ = |a·w mod N⟩ on an n-qubit work register (leaving w ≥ N alone). Because gcd(a, N) = 1, multiplication by a permutes 0…N−1, so U_a permutes basis states: reversible, hence unitary. Write x = Σ xj2ʲ in binary; then ax = Π (a2ʲ)xj. So start the work register in |1⟩ and let counting qubit j control multiplication by bj = a2ʲ mod N:

c0     |0⟩─H──●─────────────────────────┤       ├─ y0
c1     |0⟩─H──┼───────●─────────────────┤ QFT⁻¹ ├─ y1
 :            │       │                 │       │  :
c(t−1) |0⟩─H──┼───────┼─── … ─────●─────┤       ├─ y(t−1)
              │       │           │
work   |1⟩──[×b0]───[×b1]─ … ─[×b(t−1)]─────────────

b_j = a^(2^j) mod N        controlled-(×b_j) = controlled-U_a^(2^j)

This is lesson 6's phase-estimation circuit with U = U_a. The new ingredient is how controlled-Ua2ʲ gets built: it is multiplication by the single constant bj, and bj+1 = bj² mod N is one classical squaring away (square-and-multiply), done before the quantum computer starts. For N = 21, a = 2 the constants are 2, 4, 16, 4, 16, 4, 16, 4, 16.

The trap: “controlled-U2ʲ means applying U 2ʲ times” That would cost 1 + 2 + … + 2t−1 = 2ᵗ − 1 ≥ N² multiplications, exponential in n. For a generic unitary, phase estimation to t bits really does need about 2ᵗ uses of U. Shor's algorithm is efficient only because powers of Ua cost the same as Ua.

Cost: each controlled multiplication by a constant is O(n²) gates with schoolbook arithmetic, and there are t ≈ 2n of them, so O(n³); the inverse QFT adds only O(n²) (Watrous).

Why starting in |1⟩ is enough

Phase estimation wants an eigenstate of U, and you cannot write one down for Ua without knowing r. First, the one-line argument the cryptography lesson's teacher tip promised: since ar ≡ 1, Uar = I, so any eigenvalue λ satisfies λr = 1 and is an r-th root of unity e2πik/r. On the orbit 1, a, a², … the eigenstates are explicit:

|ψ_k⟩ = (1/√r) Σ_(s=0)^(r−1) e^(−2πiks/r) |a^s mod N⟩        U_a|ψ_k⟩ = e^(2πik/r) |ψ_k⟩

(1/√r) Σ_k |ψ_k⟩ = |1⟩        since Σ_k e^(−2πiks/r) = r if s = 0, and 0 otherwise

So |1⟩, the easiest state to prepare, is already an equal superposition of all r eigenstates. Phase estimation on it acts like phase estimation on a uniformly random |ψk⟩: each controlled multiplication kicks back a phase, and the output satisfies y/Q ≈ k/r for a random k. For N = 15 the phases are 0, 1/4, 1/2, 3/4, which with Q = 8 is y = 0, 2, 4, 6, each with probability 1/4: the comb view and the eigenvalue view describe the same circuit.

From y to r: continued fractions

You hold y and Q, and y/Q ≈ c/r with c and r unknown, r < N. This is why Q exceeds N²: two different fractions with denominators ≤ N differ by at least 1/N² > 1/Q. If y lands within 1/2 of a peak, |y/Q − c/r| ≤ 1/(2Q), so c/r is the only fraction with denominator ≤ N that close. Continued fractions find it: run Euclid's algorithm on (y, Q) for the partial quotients an, build convergents pn/qn with pn = anpn−1 + pn−2 and qn = anqn−1 + qn−2, and keep the last convergent with denominator ≤ N (proofs: de Wolf §5.4).

Worked example: N = 21, a = 2, Q = 512 (441 < 512 ≤ 882, so t = 9), measured y = 85 
512 = 6·85 + 2       a1 = 6
 85 = 42·2 + 1       a2 = 42
  2 = 2·1  + 0       a3 = 2            85/512 = [0; 6, 42, 2]

convergent  1/6     42/253    85/512
den ≤ 21?   yes     no        no         →  c/r = 1/6,  r = 6
closeness   |85/512 − 1/6| = 1/1536  ≤  1/1024 = 1/(2Q)
check       2^6 = 64 = 3·21 + 1 ≡ 1 (mod 21)
factor      r even, 2^3 = 8 ≢ −1 ≡ 20 (mod 21)
            gcd(8 − 1, 21) = 7      gcd(8 + 1, 21) = 3      21 = 3 · 7
That is the cryptography lesson's by-hand practice answer, now produced by a single measurement.

When a run fails. Every candidate is checked classically, so a failure costs a rerun, never a wrong answer.

  • y = 0 means c = 0, which says nothing about r. Rerun.
  • gcd(c, r) > 1 hides part of r. y = 171 = [0; 2, 1, 170] has convergents 1/2, 1/3, so r′ = 3, but 2³ = 8 ≢ 1 (mod 21): the peak was 2/6. A run giving y = 256 (1/2) yields r′ = 2, and lcm(3, 2) = 6. Taking the LCM of denominators across runs is the standard fix.
  • A missed peak (about 21% of runs for N = 21) may give a wrong candidate, which the ar ≡ 1 check catches.
  • r odd, or ar/2 ≡ −1: pick a new a. For odd N that is not a prime power, each random a splits N with probability at least 1/2 (Watrous).
Keep this in perspective Only order finding is quantum. Choosing a, precomputing bj, continued fractions and the gcds are all classical, and no step “tries every factor”. The speedup is real but stated carefully: O(n³) gates against the sub-exponential GNFS is a superpolynomial gap over the best known classical algorithm. No one has proven that factoring is classically hard, so this is not a proven exponential separation. Lesson 8 places it on the complexity map.

What Shor breaks, and what it doesn't

Shor's paper solves factoring and discrete logarithms with the same period-finding core (discrete log uses two exponent registers), and the same method works in elliptic-curve groups (costed below). That covers the public-key schemes in wide use today:

scheme                     hard problem             quantum status
RSA                        factoring                broken (order finding)
finite-field DH, DSA       discrete log mod p       broken (Shor's DLP variant)
ECDH, ECDSA, EdDSA         elliptic-curve DL        broken (same idea, EC group)
AES-128/256, SHA-2/3       no hidden period         generic (Grover-type) only
ML-KEM (FIPS 203)          module lattices          no known efficient attack

Diffie-Hellman rests on the discrete log problem and elliptic-curve cryptography on its elliptic-curve version, so both fall on the same timeline as RSA. Symmetric ciphers and hashes have no known hidden-period structure to exploit; for key search and preimages the best known attack is generic Grover search, provably limited to a square-root speedup, and NIST's draft plan (below) expects its symmetric primitives with at least 128-bit classical security to stay adequate. For key exchange the replacement is the lattice-based ML-KEM, “believed to be secure, even against adversaries who possess a quantum computer” (FIPS 203, August 2024); how lattices work is Cryptography lesson 7.

Why migrate before such a machine exists: harvest now, decrypt later. Traffic recorded today can be decrypted once a large quantum computer runs. NIST IR 8547 (initial public draft, November 2024, still a draft as of October 2026) proposes deprecating RSA and elliptic-curve algorithms at 112-bit strength after 2030 and disallowing all quantum-vulnerable public-key algorithms after 2035.

What it would cost (as of 2026)

With perfect qubits, the textbook layout needs about 3n qubits (2n counting, n work), and known tricks bring that to slightly more than 2n, so a bit over 4,096 for RSA-2048 (de Wolf, §5.3). Real qubits are noisy, so each perfect qubit must be an error-corrected logical qubit built from many physical ones. Published physical-qubit estimates, all assuming a physical error rate of 10⁻³ (0.1%) and a 1 µs error-correction cycle, have fallen fast:

  • RSA-2048: 20 million qubits, about 8 hours (Gidney & Ekerå, 2019).
  • RSA-2048: under 1 million qubits, under a week (Gidney, 2025), on the same nearest-neighbor square grid with surface codes.
  • RSA-2048: under 100,000 qubits, about a month (Webster et al., 2026), using QLDPC codes, which need longer-range qubit connections than a nearest-neighbor grid.
  • ECC-256: under 1,200 logical qubits; minutes on under 500,000 physical qubits (Babbush et al., 2026).
The trap: “RSA needs about 4,096 qubits, so it is nearly here” That figure counts perfect logical qubits. The numbers that matter are physical-qubit counts at a stated error rate, and every estimate above is a paper design for a machine that does not exist yet. The estimates fall because of cheaper arithmetic, Shor variants that trade more runs for smaller registers, and better error-correcting codes and layouts; the period-finding core is the same one you just traced. Lesson 10 covers what today's hardware can actually do.
