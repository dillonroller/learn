Coordinate Frames & Orientation Cheat Sheet

The compressed version of lesson 1. Pose, quaternions, and the scalar-first/scalar-last gotcha.

Core terms

TermDefinition
PosePosition (x, y, z) + orientation, together, relative to some frame.
Reference frameAn agreed origin + set of axes everything is measured against.
World frameFixed frame the environment is measured in (gravity down, a fixed "forward").
Body frameFrame attached to the robot, moving with it. Relating body ↔ world frames is what ROS2's tf2 is for.
Euler angles (roll/pitch/yaw)Orientation as three sequential rotation angles. Simple to read, but suffers gimbal lock.
Gimbal lockAt certain orientations (pitch ±90°), two Euler rotation axes align and a degree of freedom is lost.
Quaternion4-number orientation representation (1 scalar + 3-vector) that avoids gimbal lock.

Decoding a single-axis-rotation quaternion

angle = 2 * acos(clamp(w, -1, 1))          // degrees or radians
axis  = whichever of x, y, z has the largest magnitude
sign  = sign of that dominant component

Only valid for quaternions representing rotation about one axis — general orientations mix all three vector components at once.

Scalar-first vs. scalar-last — know which you're holding

ConventionOrder · Used by · Identity
Scalar-first(w, x, y, z) — MuJoCo, and this project's own Go2 telemetry (unmodified pass-through). Identity (1, 0, 0, 0)
Scalar-last(x, y, z, w) — ROS2 geometry_msgs/Quaternion. Identity (0, 0, 0, 1)

A bare 4-number array never tells you which convention it's in — that has to come from documentation or code. Get it backwards and nothing crashes; it just silently computes the wrong orientation.

Worked example: real robot telemetry

Sample from a captured mission log, end of a stand-up ramp (pct: 1.0): [0.9998458, -0.0000213, -0.017562, -0.0000564]
