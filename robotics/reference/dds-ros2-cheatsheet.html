DDS & ROS2 Cheat Sheet

The compressed version of Lesson 2 — vocabulary, the stack, and the real topic names this project uses.

Vocabulary

TermMeaning here
PublisherSends messages tagged with a topic name; doesn't know or care who's listening
SubscriberRegisters interest in a topic name; doesn't know or care who's sending
TopicA named channel both sides agree on, e.g. rt/lowcmd
Domain (domain_id)An isolation boundary — different domain ids map to different discovery ports, so participants on different domains never discover each other
DDSData Distribution Service — the decentralized (no broker) pub/sub middleware standard this project's SDK and ROS2 itself both use
Node (ROS2)One process, one job — a driver, a planner, a logger
Service (ROS2)Request/response call, for one-off actions (e.g. "reset the map")
Action (ROS2)Long-running, cancelable, progress-reporting call (e.g. "navigate to this waypoint")

The stack, bottom to top

LayerWhat it is
Cyclone DDSThe wire protocol/middleware — decentralized pub/sub over UDP, domain-scoped
unitree_sdk2pyPython bindings that talk this DDS interface directly — ChannelPublisher / ChannelSubscriber
unitree_ros2Bridges the same DDS traffic into ROS2 nodes/topics — no new transport, just ROS2 conventions on top
ROS2 toolingRViz, ros2 bag, nav2 — standard tools that only understand the ROS2 layer

This project's real topics

rt/lowcmdYour script → robot. Per-joint q, dq, kp, kd, tau commands (see the PD cheat sheet)
rt/lowstateRobot → your script. IMU, all 12 motor_state entries, foot_force, battery, etc.
Default domaindomain_id=1, interface lo0 on macOS (loopback)
