Locomotion & Balance Cheat Sheet

The compressed version of Lesson 6 — definitions, the static-vs-dynamic distinction, and this project's own real balance-coupling bug.

Core definitions

TermDefinition
Center of mass (CoM)Roughly, the average position of all the robot's mass (torso + legs), weighted by where that mass actually is.
Support polygonThe convex shape formed by connecting the ground-contact points of every foot currently touching the ground.
Statically stableThe CoM's straight-down projection onto the ground falls inside the current support polygon.
Stability marginThe distance from that projection to the nearest edge of the support polygon. Bigger margin = more disturbance the robot can absorb before tipping.
Zero-moment point (ZMP) / center of pressure (CoP)The more general, moving-robot version of the same test — used instead of plain CoM once the robot isn't standing still. Coincides with the CoM projection when the robot is motionless.
Linear Inverted Pendulum Model (LIPM)A simplified model — robot as one point mass on a massless rod at constant height — used to plan how the CoM should move during walking, because its trajectory has a closed-form solution.

Static vs. dynamic balance

Standing  /  Walking
Support polygonFixed (all feet down)  /  Continuously reshaping as feet lift/land
What's requiredKeep CoM inside one fixed polygon  /  Keep CoM inside a moving target, planned ahead of each footstep
Failure modeCoM drifts outside a static base  /  CoM isn't positioned correctly before the next foot lifts
This project's statusPer-joint PID+I holds one tuned pose (see below) — not CoM-aware  /  Not attempted yet

This project's real balance-coupling bug

What was triedAdded an integral gain (KI) per joint to run_stand_mission.py to fix steady-state droop (Lesson 4)
KI=20Every joint's own PID math still correct in isolation — but max error grew to ~0.29 rad and the robot oscillated
WhyAll 4 legs share one rigid body; one leg's correction shifts load on the other three, which then "correct" into a growing sway — an emergent whole-body effect, not a per-joint bug
KI=6 (shipped)Converged cleanly, reproducible: max_joint_error ≈ 0.028 rad over multiple fresh-sim runs
What that does not proveThe controller is still 12 independent joint loops — nothing tracks CoM or the support polygon. It holds this one symmetric, pre-balanced pose; it is not a general balance controller.
